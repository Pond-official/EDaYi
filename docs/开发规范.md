# 开发规范（提交前必读）

本项目为纯本地开发（无远端 CI），所有提交前校验通过本地一条命令完成。

## 提交前校验（一条命令）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify.ps1
```

该脚本按顺序执行三道关卡，任一关卡失败即非 0 退出（fail-fast）：

| 关卡 | 内容 | 判定 |
|---|---|---|
| 1/3 | 状态键契约校验（`node tools/check_storage_keys.mjs`） | 出现未登记/类别不符的状态键即失败 |
| 2/3 | DevEco Code Linter（配置 `code-linter.json5`） | 出现 **Error** 级问题即失败；Warning 仅报告不拦截 |
| 3/3 | 单元测试（hypium，Pond 模块，当前 62 用例） | `Failure/Error` 非 0 或未全过即失败 |

各关卡也可单独执行：

```powershell
# 状态键契约校验
node tools\check_storage_keys.mjs

# Code Linter（表格报告）
devecocli check lint

# 单元测试
```

## 状态键契约（任务 11）

- `@StorageProp` / `@StorageLink` / `@LocalStorageProp` 的装饰器参数**必须是字符串字面量**
  （ArkUI 限制，传常量编译不通过），因此状态键无法收口为常量。
- 全部 38 个状态键登记在 `products/Pond/src/main/ets/constants/StorageKeys.ets`
  （23 个 AppStorage 键 + 15 个卡片 LocalStorage 键），每条注明类型 / 写入方 / 读取方。
- **新增 / 改名状态键**：先在 `constants/StorageKeys.ets` 按格式登记
  （`// [AppStorage] 键名 | ...` 或 `// [LocalStorage] 键名 | ...`），再写装饰器；
  否则 `tools/check_storage_keys.mjs` 与 `scripts/verify.ps1` 会直接报错。

## 颜色规范（任务 10）

- 视图 / 页面 / 卡片层**禁止新增硬编码 hex**（`'#RRGGBB'`）。
- 颜色统一使用 `products/Pond/src/main/ets/theme/AppColors.ets` 的具名常量；
  新语义色先在该文件登记（命名体现语义而非色值），再引用。
- 不使用 `$r('app.color.x')`：`ZcpRadarChart` 的 Canvas 绘制与卡片侧取不到资源解析值，
  代码常量是唯一可行方案。

## @Builder 传参规则（任务 9 系列实证）

`@Builder` **按值传参不随状态刷新**（值在调用瞬间定格），拆分大 build 时这是最大回归源。实证规则：

- **按引用传递仅一种形式生效**：形参为**恰好一个**显式 interface/class 类型，调用处直接传
  **单参对象字面量** `MyBuilder({ key: this.val })`。对象字段内的计算表达式亦可
  （`selected: this.offset === 0` 实证）；多参数、传变量、传 `this.xxx` 单值均按值冻结。
- **嵌套按值子 Builder 不会被父级重渲刷新**：父 Builder 改成按引用后，体内直接调用的
  按值子 Builder 仍冻结在旧参。两种解法：**内联展开**（如汇总卡单元格、上下文信息行），
  或靠 **ForEach key 驱动重建**（key 并入变化字段，key 变则整棵子树销毁重建）。
- **ForEach key 必须并入所有驱动重建的变化字段**（状态 + 内容字段），不要只用稳定 ID：
  key 不变时子树按值参数不更新（成绩行/分组指纹需含 `credit`/`gpaPoint`，
  明细展开卡需含 `detailZbdm`/loading/条数，倒计时行需含 days）。
- 弹层持有可变输入时上移到 View 层：根节点 `bindSheet($$this.show, this.sheetBuilder(), …)`
  + 私有 @Builder 体内直读状态（设置页自定义提前时间弹层实证）。
- 已按此规范整改的模块 Builder：首页 / 成绩 / 综评 / 选课 / 设置 / 关于 / 桌面卡片
  （新增 `XxxCardParams` 接口 + 单参对象字面量调用，见各 `*Cards.ets`）。

## Code Linter 已知基线

原 `scripts/verify.ps1` `$KnownLintErrors` 白名单的两条 Error 级问题已改为**源头处理**，白名单现为空
（任何新 Error 级问题都会直接挂 Gate 2）：

- `data/ReminderScheduler.ets` `@typescript-eslint/await-thenable`（ensureNotificationEnabled）：
  `notificationManager.requestEnableNotification` 在 SDK 中为回调+Promise 双重载，
  eslint 解析时命中 void 重载导致误报。**已修复**：先收敛到显式 `Promise<void>` 变量再 `await`，
  规避误报且运行语义不变。
- `data/SelectionRepository.ets` `@security/no-unsafe-aes`（encryptPassword）：
  选课系统（jwxk）服务端登录协议强制 AES-128-ECB-PKCS7（CryptoJS 兼容实现，
  密钥为其登录页 HTML 公开硬编码值），算法由校方服务端决定，无法改为 GCM 等安全模式。
  **已在源头加 `eslint-disable-next-line` 抑制注释**（协议约束，非本方可修复项）。
- 另有 3 条 `@performance/avoid-overusing-custom-component-check` 告警
  （FrostBand / HiddenWeb / AppLogCard）为有意保留的组件化设计，均已在声明处加
  `eslint-disable-next-line` 注释说明理由（跨文件复用 / 懒加载挂载 / 独立状态订阅）。
- 向白名单重新追加条目必须在本文档写明理由。

## 其他约定

- ArkTS 严格模式：禁 `any` / `unknown` / 索引签名 / 结构化类型，对象字面量必须有显式类型。
- 禁止用 PowerShell 的 `Get-Content`/`Set-Content` 读写含中文的 `.ets` 源文件
  （PS 5.1 默认 GBK 会损坏 UTF-8 文件），请使用编辑器或 UTF-8 安全的工具。
- 每次功能改动需保证 `devecocli build` 成功、62 个单测全绿后再提交。
